Documentation

This is some documentation about the system, what the general process is, and how things work underneath.

Full life-cycle of a request

  1. Student logs in, selects the project(s) they want and submits a formal request .
    This create a new request object in the database, per project, with a status of 'NEW', and a decision of 'ON-HOLD'.
  2. Project supervisors log in and view their requests.
    They can set the decision on each one to accept or reject, and rejecting requires an explanation to be provided.
    This moves the request to the 'PROCESSED' state.
    The student is not informed of any change at this point.
  3. An administrator logs in and views all processed requests.
    If they agree with the decision they mark the request as verified and its state changes to 'VERIFIED'
    If not they can discuss with the supervisor.
    The student is not informed of any change at this point.
  4. Once all the requests in a round have been dealt with an administrator can release the responses to the students.
    This emails any student that has a request in the 'VERIFIED' state telling them there has been change, and they should log into the site to view it.
    This changes the state of the request to 'COMPLETED'.
    Any requests that have not been verified stay in the state they are in.

Administrator Information

This is some information that users with administrative privileges on the system will find useful.

Request processing

The various views let you push requests through, and change decisions.

'See all requests' has a various filters available at the top of the page.
The 'New' filter shows you all the requests that supervisors have yet to processes.
On this page you can use the 'Move to On-Hold for supervisor' button to make an unprocessed request appear in the 'Verify supervisor responses' page where you can edit it further.
